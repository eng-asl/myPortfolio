Protocol Architecture & Connection Modes

FTP is one of the oldest Internet protocols and runs at the application layer of the TCP/IP stack alongside HTTP and POP. Unlike single-socket protocols, it splits control signaling and data transfer across two TCP connections.

CH 01

Control Channel (TCP 21)

Carries commands such as USER, PASS, LIST, STOR, RETR, PORT, PASV, and numeric status codes. Remains open across the session.

CH 02

Data Channel (Separate TCP)

Dedicated TCP connection opened per directory listing or file transfer. Both channels are bidirectional once established.

PORT

Active Mode (Server -> Client)

Client sends PORT; server initiates the data socket from TCP port 20 to the client port. Client firewalls or NAT often block it.

PASV

Passive Mode (Client -> Server)

Client sends PASV; server returns an ephemeral listening port (e.g. 52000) so the client initiates both sockets cleanly through NAT.

Reading the mode diagrams

Arrows in Active and Passive diagrams indicate which side initiates the TCP connection, not the direction of file transfer. Transfers may also resume when supported by both endpoints.
